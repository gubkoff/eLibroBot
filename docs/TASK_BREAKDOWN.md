# Задачи по шагам и подшагам: eLibroCargoReportBot

Чёткая разбивка реализации на шаги и подшаги. Выполнять по порядку; каждый подшаг можно отмечать по мере выполнения.

---

## Шаг 1: Скелет проекта

**Цель:** бот запускается из venv и отвечает на `/start`.

| № | Подшаг | Действие | Готово |
|---|--------|----------|--------|
| 1.1 | Зависимости | Создать `requirements.txt`: `aiogram>=3.0`, `pydantic-settings`; при необходимости пакет для `.env` (например `python-dotenv` или использовать встроенную поддержку pydantic-settings). | |
| 1.2 | Шаблон конфига | Создать `.env.example` с переменными `BOT_TOKEN=`, `SOURCE_GROUP_ID=`, `TARGET_GROUP_ID=` и комментариями (без реальных значений). | |
| 1.3 | Загрузка настроек | Создать `config.py`: класс настроек на `BaseSettings` (pydantic-settings), поля для перечисленных переменных, чтение из `.env`. | |
| 1.4 | Точка входа | Создать `main.py`: создать экземпляр `Bot` и `Dispatcher` (aiogram 3), зарегистрировать хендлер команды `/start` с приветствием (упомянуть имя бота eLibroCargoReportBot), запуск через `dp.start_polling()`. | |
| 1.5 | Игнор в Git | Создать `.gitignore`: `.env`, `__pycache__`, `*.pyc`, `venv/`, `.venv/`. | |
| 1.6 | Виртуальное окружение | В корне проекта выполнить `python -m venv venv`; активировать venv; выполнить `pip install -r requirements.txt`. | |
| 1.7 | Проверка | Запустить `python main.py` из активированного venv; в Telegram отправить боту `/start` и убедиться в ответе. | |

**Результат шага:** бот стартует по `python main.py` и на `/start` отвечает приветствием.

## Шаг 2: Парсер сообщений

**Цель:** из текста сообщения получать список записей `Record`.

| № | Подшаг | Действие | Готово |
|---|--------|----------|--------|
| 2.1 | Пакет | Создать каталог `parser/` и файл `parser/__init__.py`. | |
| 2.2 | Модель данных | В `parser/models.py` описать dataclass `Record` с полями: `date` (date), `amount` (Decimal), `category` (str); при необходимости `raw_text` (str). | |
| 2.3 | Формат даты | Выбрать один формат даты для первой версии (например `YYYY-MM-DD` или `DD.MM.YYYY`) и зафиксировать в коде/комментарии. | |
| 2.4 | Функция парсинга | В `parser/parser.py` реализовать `parse_message(text: str) -> list[Record]`: разбить текст по строкам; для каждой строки разбирать формат «дата сумма категория» (разделители: пробел, запятая, табуляция); приводить к типам date и Decimal; невалидные строки пропускать. | |
| 2.5 | Логирование | При пропуске невалидной строки вызывать `logging.debug` или `logging.warning` с текстом строки. | |
| 2.6 | Тесты (опционально) | Создать `tests/test_parser.py`: тесты на нескольких строках (валидные и невалидные), проверка длины списка и полей `Record`. | |
| 2.7 | Проверка | Вызвать `parse_message("2025-02-26 100 продукты")` и убедиться, что возвращается одна запись с корректными полями. | |

**Результат шага:** `parse_message(text)` возвращает список `Record` по структурированному тексту.

## Шаг 3: Калькулятор

**Цель:** по списку `Record` получить агрегаты для отчёта.

| № | Подшаг | Действие | Готово |
|---|--------|----------|--------|
| 3.1 | Пакет | Создать каталог `report/` и файл `report/__init__.py`. | |
| 3.2 | Тип результата | Определить тип результата расчёта (dataclass или TypedDict) с полями: `total`, `by_category` (dict[str, Decimal]). | |
| 3.3 | Функция расчёта | В `report/calculator.py` реализовать `calculate(records: list[Record])`: вычислить общую сумму и суммы по категориям; при пустом списке вернуть нулевые/пустые значения без исключения. | |
| 3.4 | Тесты (опционально) | Создать `tests/test_calculator.py`: тесты на наборе записей, проверка `total` и `by_category`. | |
| 3.5 | Проверка | Вызвать `calculate([Record(...), Record(...)])` и убедиться в корректных `total` и `by_category`. | |

**Результат шага:** `calculate(records)` возвращает структуру, пригодную для передачи в `pdf_builder`.

## Шаг 4: Генерация PDF

**Цель:** по результатам калькулятора и списку записей сформировать PDF во временный файл.

| № | Подшаг | Действие | Готово |
|---|--------|----------|--------|
| 4.1 | Зависимость | Добавить в `requirements.txt` пакет `reportlab`; при необходимости выполнить `pip install -r requirements.txt`. | |
| 4.2 | Сигнатура | В `report/pdf_builder.py` определить функцию `build_pdf(calculation_result, records, **meta) -> Path`. | |
| 4.3 | Содержимое PDF | Реализовать построение PDF через reportlab: заголовок отчёта (eLibroCargoReportBot), дата генерации, таблица записей и/или сводка по категориям, итоги. | |
| 4.4 | Временный файл | Сохранять PDF через `tempfile.NamedTemporaryFile(delete=False, suffix='.pdf')`; после записи закрыть файл; вернуть путь к файлу. | |
| 4.5 | Подпись | Добавить внизу страницы подпись вида «Сгенерировано: {дата/время}». | |
| 4.6 | Проверка | Вызвать `build_pdf(result, records=...)` и убедиться, что по возвращённому пути открывается корректный PDF. | |

**Результат шага:** `build_pdf(...)` возвращает путь к временному PDF-файлу, готовому к отправке.

## Шаг 5: Хендлер сообщений и пайплайн

**Цель:** по сообщению из группы-источника выполнить полный цикл и отправить PDF в группу-получатель.

| № | Подшаг | Действие | Готово |
|---|--------|----------|--------|
| 5.1 | Пакет | Создать каталог `bot/` и файл `bot/__init__.py`. | |
| 5.2 | Фильтр чата | В `bot/filters.py` реализовать фильтр для aiogram: `message.chat.id == settings.SOURCE_GROUP_ID`. | |
| 5.3 | Фильтр текста | В том же фильтре проверять наличие непустого `message.text`. Опционально: проверка `message.from_user.id in ALLOWED_USER_IDS`. | |
| 5.4 | Хендлер: парсинг | В `bot/handlers.py` в хендлере сообщения вызвать `records = parse_message(message.text)`. | |
| 5.5 | Хендлер: пустой результат | Если `not records` — выйти (или отправить в группу-источник «Нет данных для отчёта»). | |
| 5.6 | Хендлер: расчёт и PDF | Вызвать `result = calculate(records)` и `pdf_path = build_pdf(result, records=records, ...)`. | |
| 5.7 | Хендлер: отправка | Отправить PDF в целевую группу через `message.bot.send_document(chat_id=TARGET_GROUP_ID, document=FSInputFile(pdf_path), caption="...")`. | |
| 5.8 | Хендлер: очистка | После отправки удалить временный файл `os.remove(pdf_path)`. | |
| 5.9 | Обработка ошибок | Обернуть шаги парсинг–отправка в try/except: логировать ошибку; при необходимости отправить в группу-источник короткое сообщение об ошибке. | |
| 5.10 | Подключение в main | В `main.py` подключить роутер с хендлером сообщений и фильтром; команду `/start` оставить отдельно. | |
| 5.11 | Проверка | Отправить структурированное сообщение в группу-источник и убедиться, что в группу-получатель приходит PDF. | |

**Результат шага:** сообщение в группе-источнике запускает пайплайн и в группу-получатель уходит PDF.
