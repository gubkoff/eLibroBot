# Руководство заказчика: eLibroCargoReportBot

Документ описывает, как развернуть и эксплуатировать Telegram-бота, который читает сообщения «ВЗВЕШИВАНИЕ № …» из чата-источника и отправляет PDF-накладные в чат-получатель.

## 1) Обзор решения

- **Вход**: сообщения в Telegram **чате-источнике** (группа/супергруппа) в формате «ВЗВЕШИВАНИЕ № …» с полями (номер машины, веса, цена/тонна, дата взвешивания и т.д.).
- **Выход**: PDF-документ «Расходная накладная» в **чате-получателе**.
- **Дополнительно**: под PDF-сообщением могут появляться inline-кнопки режимов расчёта:
  - **Стандарт**
  - **Дозагрузка**

## 2) Требования и доступы

### 2.1 Требования к серверу/ПК

- Доступ в интернет (Telegram)
- Возможность запускать процесс бота постоянно (24/7), желательно с автоперезапуском.

### 2.2 Требования к Telegram

- Бот должен быть **добавлен** в чат-получатель и иметь право **отправлять документы**.
- Если включается режим чтения через MTProto (Telethon), аккаунт пользователя (под которым логинится Telethon) должен быть **участником чатов-источников**.

## 3) Переменные окружения и конфигурация

Настройки задаются через `.env` (пример — `.env.example`).

Ключевые параметры:

- **`BOT_TOKEN`**: токен бота из @BotFather.
- **`SOURCE_GROUP_ID`** или **`SOURCE_GROUP_IDS`**: id чата(-ов) источника.
- **`TARGET_GROUP_ID`**: id чата-получателя.

### Как получить chat id

Chat id — это “номер” вашего чата в Telegram. Он нужен, чтобы бот понимал, **из какого чата читать** и **в какой чат отправлять PDF**.

Самый простой способ для пользователей — через бота `@WhatChatIDBot`:

1. Откройте Telegram и найдите бота `@WhatChatIDBot`.
2. **Добавьте `@WhatChatIDBot` в нужную группу** (источник или получатель).
3. Бот автоматически пришлёт сообщение с **Chat ID** — скопируйте число целиком (включая минус `-`, если он есть).
4. После этого `@WhatChatIDBot` обычно **сам выходит из группы** — это нормально.

Подсказки:

- Для групп/супергрупп chat id часто выглядит как большое отрицательное число, например `-100...` — это нормально.
- Если Telegram “обновил” группу до супергруппы, chat id мог измениться — тогда его нужно получить заново.

### Частая проблема: “группа стала супергруппой”

Если Telegram “обновил” группу до супергруппы, старый `TARGET_GROUP_ID` перестаёт работать и бот получает ошибку вида:
`Bad Request: group chat was upgraded to a supergroup chat`.

Решение: заменить `TARGET_GROUP_ID` на новый id `-100...` (его Telegram обычно сообщает в тексте ошибки).

## 4) Режимы чтения сообщений (Bot API и MTProto)

### 4.1 Bot API (обычный режим)

Бот получает апдейты через Bot API.

Ограничение: Bot API **не видит** сообщения, которые в чате-источнике отправлены **другими ботами**.

### 4.2 MTProto (Telethon) — рекомендовано для групп-источников

Если в чате-источнике сообщения публикует **другой бот** (например система весов), то обычный Telegram-бот может их “не видеть”.
В этом случае включается режим **MTProto (Telethon)** — чтение идёт “как у человека”, поэтому видны сообщения и от людей, и от ботов.

При включении MTProto:

- чтение сообщений в чатах-источниках делает **Telethon** (от имени пользователя);
- PDF отправляет **бот** в чат-получатель (через Bot API).

## 5) Авторизация MTProto (Telethon)

Ниже — инструкция “как включить MTProto” и “как войти”.

### 5.0 Что нужно заранее

1) На сайте Telegram нужно получить 2 параметра для Telethon:

- `TELEGRAM_API_ID` (число)
- `TELEGRAM_API_HASH` (строка)

Где взять: откройте сайт `my.telegram.org`, войдите по номеру телефона → раздел **API Development Tools** → создайте приложение и скопируйте `api_id` и `api_hash`.

2) Аккаунт Telegram, под которым выполняется вход Telethon, должен быть **участником всех чатов-источников**.

### 5.0.1 Что добавить в `.env`

В файл `.env` (рядом с `.exe`) добавьте:

```env
TELEGRAM_API_ID=12345678
TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
```

Опционально (по желанию):

- `TELEGRAM_PHONE=+79001234567` (чтобы не вводить номер в консоли при первом входе)
- `TELEGRAM_2FA_PASSWORD=...` (если на аккаунте включён облачный пароль/2FA)
- `TELEGRAM_LOGIN_QR=1` (если хотите вход по QR)

### 5.1 Вход по номеру телефона

При первом запуске Telethon попросит:

1. Номер телефона (в формате `+7...`)
2. Код входа (код приходит **в приложение Telegram** на телефоне — уведомлением или в чат “Telegram”)
3. Если включён 2FA — пароль

После успешного входа рядом с программой появится файл `telethon.session` — это “ключ”, чтобы больше не логиниться каждый раз.

### 5.2 Вход по QR (если код не приходит / удобнее)

Используйте вход по QR:

1. В `.env` задайте `TELEGRAM_LOGIN_QR=1` (и при необходимости `TELEGRAM_2FA_PASSWORD`).
2. Запустите программу.
3. В консоли появится QR-код (или ссылка `tg://login?...`).
4. В Telegram на телефоне: **Настройки → Устройства → Подключить устройство** → отсканируйте QR.
5. Если QR “протух” (часто он живёт ~30–60 секунд), просто подождите — программа покажет новый QR, повторите сканирование.

### 5.3 Если код входа “не приходит”

- Код приходит **не по SMS**, а в приложение Telegram (уведомление или чат “Telegram”).
- Проверьте: **Настройки Telegram → Устройства** (возможны ограничения по частоте входов).
- Проверьте формат номера: `+7...` без пробелов.
- Не нажимайте “получить код” много раз подряд — лучше подождать пару минут.

## 6) Установка и запуск

Если вам передали готовую поставку с `.exe`, то установка Python и зависимостей не нужна.

### 6.1 Где должны лежать файлы

Обычно это одна папка, например `C:\eLibroBot\`, внутри:

- `eLibroBot.exe` (или как назван файл программы)
- `.env` (ваши настройки)
- `telethon.session` (появится сам после первого входа, если включили MTProto)

### 6.2 Запуск

Откройте `eLibroBot.exe`. Если включён MTProto и это первый вход — появится окно/консоль с запросом кода или с QR.

### 6.3 Проверка работоспособности (smoke)

1. Отправьте тестовое сообщение «ВЗВЕШИВАНИЕ № …» в чат-источник.
2. Убедитесь, что в чат-получатель пришло сообщение с PDF.
3. При выполнении условий появления кнопок (см. ниже) под PDF появятся `Стандарт` и `Дозагрузка`.

## 7) Автозапуск после перезагрузки

### 7.1 Windows

Рекомендуемый способ — **Планировщик заданий** (встроен в Windows). Ниже — пошагово.

#### 7.1.1 Подготовка

1. Положите папку с программой, например в `C:\apps\eLibroBot\`.
2. Убедитесь, что рядом с `.exe` лежит ваш `.env`.
3. Запустите программу вручную один раз и убедитесь, что она работает.

#### 7.1.2 Настройка планировщика

1. Откройте **Планировщик заданий**:
   - Win+R → введите `taskschd.msc` → Enter
2. Справа выберите **Создать задачу…** (не “простую”).
3. Вкладка **Общие**:
   - **Имя**: `eLibroBot`
   - Вариант “когда запускать”:
     - обычно удобно **Только при входе в систему**
   - Если нужно, отметьте **Выполнять с наивысшими правами** (обычно не требуется).
4. Вкладка **Триггеры**:
   - **Создать** → **При входе в систему** (или **При запуске компьютера**)
   - По желанию: **Отложить задачу на 30–60 секунд**, если интернет/Wi‑Fi поднимается не сразу.
5. Вкладка **Действия**:
   - **Создать** → **Запуск программы**
   - **Программа или сценарий**: путь к вашему `.exe`, например `C:\apps\eLibroBot\eLibroBot.exe`
   - **Рабочая папка**: папка, где лежит `.exe`, например `C:\apps\eLibroBot`
6. Вкладка **Параметры**:
   - Включите **Перезапускать при сбое** (например через 1 минуту, 5 попыток).
7. Нажмите **ОК**.

#### 7.1.3 Проверка

1. В планировщике найдите задачу → **Выполнить**.
2. Перезагрузите ПК и убедитесь, что программа запустилась сама.

Важно: не запускайте программу вручную, если она уже запущена планировщиком (иначе будет 2 экземпляра).

### 7.2 Linux (systemd) — рекомендуемый вариант для сервера

Обычно используют `systemd`-сервис с автоперезапуском. Типовой набор:

- отдельная директория проекта
- отдельный venv
- unit-файл `*.service` (запуск `python main.py`)
- `Restart=always`
- `WorkingDirectory=...`
- переменные окружения через `.env`/EnvironmentFile

Если вы скажете вашу ОС/дистрибутив (Ubuntu/Debian/CentOS), мы подготовим готовый `systemd` unit под ваш сервер.

### 7.3 macOS (launchd)

Для macOS обычно используют `launchd` (plist) либо запуск в docker. Если это ваш сценарий — сообщите, мы добавим готовую инструкцию.

## 8) Обновление версии

Рекомендуемый порядок:

1. Остановить бота (сервис/процесс).
2. Обновить файлы программы (заменить папку проекта на новую версию, присланную разработчиком).
3. Обновить зависимости:

```bash
pip install -r requirements.txt
```

4. Запустить бота снова.
5. Проверить по логам, что бот подключился и отправляет PDF.

Rollback (откат):

- Хранить резервную копию предыдущей версии папки проекта и при проблемах вернуть её обратно.

## 9) Кнопки режимов “Стандарт / Дозагрузка”

### 9.1 Когда кнопки появляются

Кнопки под PDF-сообщением в чате-получателе показываются **только если**:

- в чате-источнике найдено **предыдущее распознаваемое** взвешивание с тем же `plate_number`,
- и разница между **“Дата взвешивания”** текущего и предыдущего сообщения **не более 1 часа**.

Если “Дата взвешивания” отсутствует в текущем сообщении, кнопки не показываются.

### 9.2 Что делает “Стандарт”

- Накладная пересобирается обычным способом (как без дозагрузки).
- В сообщении в чате-получателе заменяется PDF-документ (можно скачать стандартный вариант).

### 9.3 Что делает “Дозагрузка”

В режиме “Дозагрузка” бот ищет **первое по времени предыдущее** взвешивание этой машины (тот же `plate_number`) и применяет формулу:

- **Тара** = **Брутто** предыдущего взвешивания
  - если в предыдущем есть “Вес с корректировкой”, то брутто для формулы = `тара + корректировка`
  - иначе берётся брутто из сообщения
- **Нетто** = “Вес с корректировкой” текущего, если он есть, иначе “Нетто” текущего
- **Брутто** = `Тара + Нетто`
- **Сумма** = `(Нетто / 1000) * Цена_за_тонну`
- **НДС** = `Сумма / 116 * 16`

В сообщении в чате-получателе заменяется PDF-документ (можно скачать вариант с дозагрузкой).

### 9.4 Важные ограничения

- Номер взвешивания **не меняется**.
- Количество наименований **не меняется** (по умолчанию 1).
- Шаблон накладной стандартный — меняются только расчётные значения.

## 10) Логи и диагностика

### 10.1 Что смотреть в логах

- запуск Bot API (aiogram) и MTProto (Telethon)
- обработка входящих сообщений (chat_id, распознавание парсером)
- отправка PDF в target-чат
- ошибки Telegram (нет прав, неверный chat_id, миграция чата)

### 10.2 Типовые проблемы и решения (FAQ)

**Проблема:** `group chat was upgraded to a supergroup chat`  
**Причина:** чат мигрировал, id изменился.  
**Решение:** обновить `TARGET_GROUP_ID` на новый `-100...` (из текста ошибки), перезапустить бота.

**Проблема:** бот не отправляет PDF, “not enough rights / send documents”  
**Причина:** нет прав в чате-получателе.  
**Решение:** выдать боту права администратора (или хотя бы “Отправка сообщений/документов”).

**Проблема:** MTProto не читает сообщения  
**Причина:** нет авторизации/сессии или пользователь не в чате-источнике.  
**Решение:** проверьте, что:

- в `.env` заполнены `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`;
- вы один раз успешно вошли (есть файл `telethon.session` рядом с программой);
- аккаунт Telegram, под которым вы входили, состоит в чате-источнике.

**Проблема:** “кнопки не появились, хотя были 2 взвешивания”  
**Причина:** нет “Дата взвешивания” или разница по датам > 1 часа.  
**Решение:** проверить, что поле “Дата взвешивания” заполнено корректно в обоих сообщениях.

## 11) Безопасность

- `.env` и `telethon.session` храните **только на рабочем ПК/сервере** и не пересылайте в общие чаты/облака без необходимости.
- Токен бота и параметры Telethon считать секретами (ограничить доступ на сервере).
- При компрометации токена — перевыпустить токен у @BotFather и обновить `.env`.

## 12) Чек-лист эксплуатации

Перед вводом в эксплуатацию:

- [ ] Бот добавлен в чат-получатель и имеет права на отправку документов.
- [ ] `SOURCE_GROUP_ID(S)` и `TARGET_GROUP_ID` актуальны (в т.ч. `-100...` для супергрупп).
- [ ] MTProto настроен (если нужен) и сессия авторизована.
- [ ] Отправка тестового взвешивания даёт PDF в target-чате.
- [ ] При двух взвешиваниях одной машины в пределах 1 часа по “Дата взвешивания” появляются кнопки.
- [ ] Нажатие `Стандарт` / `Дозагрузка` обновляет PDF в том же сообщении.
